# 学习打卡系统设计

## 目标

为单个用户提供微信小程序和 Windows EXE 两个入口。系统从现有考研规划 Excel 读取每日任务，在小程序或桌面端完成打卡、计时和复盘后同步到云端，并由 Windows 客户端自动把实际小时、完成率、状态和复盘写回 Excel。电脑关机时，CloudBase 定时任务仍通过 WxPusher 发送微信提醒。

## 架构

- 微信小程序：微信登录、今日任务、自动计时、手动补录、历史、周统计、提醒设置和设备配对。第一版不允许修改原计划。
- Windows EXE：WPF 单文件应用，提供今日面板、托盘提醒、开机启动、Excel 路径设置、立即同步和失败队列。
- CloudBase：保存用户、计划、打卡、计时、设备令牌和提醒设置；云函数提供小程序调用、桌面 HTTP 接口和定时任务。
- WxPusher：只接收提醒文字和用户 UID。AppToken 仅保存在云函数环境变量中。
- Excel：继续作为计划来源。云端记录是打卡事实来源；EXE 负责将事实投影回工作簿。

## 数据流

1. EXE 首次读取 `每日执行_2026`，将任务转换为标准计划模型并推送云端。
2. 小程序通过 `wx.login` 识别用户，读取指定日期的计划。
3. 用户开始任务时写入服务端开始时间；切出微信后计时继续。停止时服务端计算时长，单次超过 4 小时要求确认。
4. 打卡记录采用请求 ID 保证幂等。离线请求先进入本地队列，恢复网络后顺序提交。
5. EXE 每分钟拉取变化，Excel 未占用时写回 K、M、N 列；占用时保留待写任务并重试。
6. CloudBase 定时任务按 07:30、19:00、22:30 和周日 21:30 检查状态并调用 WxPusher。

## 规则与边界

- 单用户、单份主规划，不做社交、排名或多人协作。
- 小程序可新增临时任务，但不改 Excel 原计划文字。
- 冲突以云端最新 `updatedAt` 为准，覆盖前保留同步日志。
- 期末预备周和考试周只提醒未暂停任务，843 和考研新内容不参与催促。
- 个人订阅号不承担自动提醒；后续仅作为小程序或 H5 的入口。
- 没有 AppID 时，小程序使用本地 Mock 数据，EXE 使用本地 JSON 模拟云端，所有云接口保持相同模型。

## 界面方向

界面采用安静、务实的“学习工作台”风格：米白背景、深墨色文本、青绿色进度、金色截止提醒和少量红色风险状态。信息按时间线和任务清单展开，不使用营销式大标题或装饰性卡片。所有操作均有明确的加载、离线、同步中、失败和完成状态。

## 验收标准

- 自动计时、手动补录、单任务互斥和 4 小时保护通过测试。
- WPF 应用可启动、托盘运行、持久化本地数据并生成同步队列。
- 对规划 Excel 的测试副本写入正确列，不破坏公式和其他工作表。
- 小程序四个页面可使用 Mock 数据完成主要流程，JavaScript/JSON 静态检查通过。
- CloudBase 云函数覆盖登录、计划、打卡、计时、配对、统计和提醒。
- 生成可运行的 Windows 单文件 EXE，并提供从注册小程序到部署云函数的教程。
